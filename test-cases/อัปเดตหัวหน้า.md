## ทำอะไรไปแล้ว

**ปรับเทสเคส**
- เทียบกับเอกสาร BA แล้วเพิ่มเคส Admin 11 เคส
- ย้ายเคสสิทธิ์ 6 เคสจากภาคผนวกกลับเข้าชุดหลัก
- แก้เคสตามหน้า login ใหม่ที่รวมเป็นหน้าเดียว

**หน้า login และสมัคร: 35 จาก 66 เคส** (Passed 12 / Failed 10 / Pending 13)
- เทสใน Expo Go บน Android emulator แบบปิดเน็ต
- ดูช่องเบอร์ แป้นพิมพ์ error การหมุนจอ และการสลับแอป
- ยังไม่ได้สมัครหรือ login สำเร็จจริง

**API: 44 จาก 87 เคส** (Passed 33 / Pending 11)
- รัน Express ในเครื่อง ไม่ต่อ Supabase ใช้ Twilio fake และส่วนใหญ่ใช้ ML จำลอง
- ดู API key แต่ละ scope, validate ข้อมูลของ predict, cooldown และ Admin API
- ใช้คีย์ผิดได้ 401, admin ใส่รหัสผิด 5 ครั้งแล้วครั้งที่ 6 ได้ 429, อุปกรณ์เงียบครบ 16 นาทีขึ้น offline

**การโทรแจ้งเหตุ: 13 จาก 28 เคส** (Passed 12 / Failed 1)
- ไม่มีใครกดรับทราบ ระบบสั่งโทรและ SMS ครบ 2 เบอร์ที่วินาทีที่ 60.1
- ack ที่วินาทีที่ 55 ยกเลิกได้ ดูต่อถึงวินาทีที่ 90 ไม่มีการโทร ส่วน ack หลังหมดเวลาได้ 409
- เปิด AI แต่ไม่มีคีย์ ตอบช้า หรือคีย์ถูกปฏิเสธ ระบบยังสั่งโทรที่วินาทีที่ 60 ด้วยข้อความมาตรฐาน
- ทั้งหมดเป็นการโทรจำลอง และยิง ack เข้า API ตรง ไม่ได้กดในแอป

**ML service: 7 จาก 16 เคส** (Passed 3 / Failed 1 / Pending 3)
- เปิดด้วยโมเดลจริง สลับ `rf_v1` กับ `rf_v2_event` ได้ ใส่ชื่อโมเดลผิดแล้วเปิดไม่ขึ้นตามที่โค้ดเขียนไว้
- ใช้ข้อมูลจำลอง ยังไม่ได้วัดความแม่น

**ความปลอดภัย: 5 จาก 22 เคส** (Passed 3 / Failed 1 / Pending 1)
- ไม่ได้ login อ่านตาราง `houses` ได้ 0 แถว (เคสนี้ยิงฐานจริงแบบอ่านอย่างเดียว)
- CORS บล็อก origin ที่ไม่อนุญาต
- ไม่พบคีย์จำลองใน log และไม่พบค่าจริงของ service_role / Twilio / Typhoon ในรีโป

## ยังไม่ได้ทำ

- สมัคร, login, logout กับบัญชีจริง
- หน้าหลัง login: แจ้งเตือน, ตั้งค่า, เบอร์ฉุกเฉิน, อุปกรณ์, สมาชิก (ชีต 2–7 รวม 173 เคส ยังไม่ได้เทสเลย)
- สิทธิ์รายบ้าน, RLS ส่วนที่เหลือ และการกู้ timer หลังรีสตาร์ต
- กดรับทราบในแอป, push จริง, โทรจริง และ AI ตอนตอบปกติ
- ความแม่นของโมเดล
- ESP32 และล้มจริงทั้งระบบ (E2E)
- Render
- เทสซ้ำบั๊ก เพราะยังไม่มีข้อที่แก้
- SQL ข้อมูลทดสอบและบัญชี A–D ชุดเดิมหาย ยังไม่ได้ทำใหม่
- เคสของหน้า `get-started` และ `activity-log` ยังไม่ได้เขียน
