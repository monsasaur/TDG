## 🎬 Demo Flow (1 นาที 30 วินาที)

### ⏱ [0:00–0:15] เปิด — แสดงฮาร์ดแวร์

**ทำ:** ยก ESP32 ขึ้นให้คนเห็น

**พูด:**
> "นี่คือ ESP32 จริงในระบบครับ ตัวเล็กแค่นี้ — ตัวที่ 1 วัด CSI, ตัวที่ 2 ส่งสัญญาณ
>
> ผมขอโชว์เป็น **live** เลยครับ แต่บอกก่อนว่า demo นี้โชว์เฉพาะ **raw signal** ยังไม่เข้า model นะครับ"

---

### ⏱ [0:15–0:30] Terminal 1 — UDP Stream

**ทำ:** สลับมาที่ Terminal 1 (ตัวเลข packet ไหลเรียงตลอด)

**สิ่งที่เห็นบนจอ:**
```
[12:34:01.234] device=esp32-01 packet#1234 subcarriers=52 rssi=-45
[12:34:01.244] device=esp32-01 packet#1235 subcarriers=52 rssi=-46
[12:34:01.254] device=esp32-01 packet#1236 subcarriers=52 rssi=-44
...
```

**พูด:**
> "หน้าจอนี้ — แล็ปท็อปกำลังรับ UDP packet จาก ESP32 ผ่าน hotspot
>
> *(ชี้ตัวเลขที่ไหล)* — packet เข้ามา **100 ต่อวินาที** ไม่หยุด
>
> แต่ละ packet มี CSI **52 subcarriers** คือคลื่น WiFi แยกเป็น 52 ความถี่"

---

### ⏱ [0:30–1:15] กราฟ — โชว์ 3 State ⭐ จุดไคลแมกซ์

**ทำ:** สลับมาที่กราฟ Terminal 2

#### State 1 — ยืนนิ่ง (10 วินาที)

**ทำ:** ยืนนิ่งหน้า ESP32 ห่าง 1.5 เมตร

**พูด:**
> "ตอนนี้ผมยืนนิ่ง — *(ชี้กราฟ)* — สัญญาณค่อนข้างราบ มี noise ตามธรรมชาติของคลื่น"

**ค้าง 5 วินาทีให้คนเห็นชัด**

#### State 2 — เดิน (10 วินาที)

**ทำ:** เริ่มเดินไปมาช้าๆ หน้า ESP32

**พูด:**
> "พอผมเริ่มเดิน — *(ชี้กราฟ)* — เส้นกราฟ**แกว่งเป็นจังหวะ**ตามก้าวเดิน
>
> ร่างกายผมไปรบกวน multipath ของ WiFi"

**เดิน 4-5 ก้าว ให้คนเห็น pattern**

#### State 3 — ล้ม (15 วินาที) ⭐⭐

**ทำ:**
1. หยุดเดิน หันหน้าผู้ฟัง 45°
2. เตือนคนดู
3. ล้มลงเบาะ **ช้าๆ** ให้เห็น phase ก่อน-ระหว่าง-หลัง
4. นอนนิ่ง 2 วินาที
5. ลุกขึ้นชี้กราฟ

**พูด:**
> "ขอโชว์ท่าล้มจริงนะครับ"
>
> *(ล้ม)*
>
> *(ลุกขึ้นชี้กราฟ)* "เห็นไหมครับ — สัญญาณ**กระชากแรง**ตอนล้ม แล้ว**ตกลงไปต่ำ**ตอนนอนนิ่ง
>
> 3 phase ชัดเจน — ก่อนล้ม ขณะล้ม หลังล้ม"

---

### ⏱ [1:15–1:30] ปิด — Transition

**ทำ:** เตรียมกดเปลี่ยนสไลด์

**พูด:**
> "นี่คือ **input ดิบ**ก่อนเข้า model ครับ
>
> สไลด์ถัดไปจะให้ดูว่าสัญญาณนี้พอเข้าระบบ end-to-end แล้วเกิดอะไรขึ้น — แต่ขอโชว์เป็น**วิดีโออัด**นะครับ เพราะ model ยังยึดติดกับห้องที่ฝึก ซึ่งเป็น limitation ที่อยู่ใน roadmap ของเรา"
>
> *(กดเปลี่ยนสไลด์)*

## 🚨 Emergency Procedures

### ❌ Scenario 1: ESP32 ไม่ส่ง UDP เลย

**สาเหตุที่เป็นได้:**
- IP มือถือเปลี่ยน (Hotspot reconnect)
- ESP32 ค้าง / boot fail
- Power Bank แบตหมด

**วิธีแก้สด (ห้ามแก้บนเวที — ตัด backup เลย):**
> "ขออภัยครับ ESP32 หลุดสัญญาณ — ขอโชว์เป็นวิดีโอที่อัดไว้แทนนะครับ"

**Action:** กด `Cmd+Tab` → เปิดวิดีโอ backup ที่อัดไว้

---

### ❌ Scenario 2: กราฟ render ค้าง

**วิธีแก้:**
> "หน้าจอ render ค้าง ขอใช้ terminal log แทนครับ"

**Action:** สลับไป Terminal ที่รัน `tcpdump` แสดง packet flow

---

### ❌ Scenario 3: ล้มแล้วกราฟไม่ตอบสนอง

**สาเหตุ:** มุม ESP32 ไม่ดี / คนยืนใกล้ ESP32 มากเกิน / ESP32 หลุดบางช่วง

**วิธีแก้:**
> *(พูดต่อนิ่งๆ ไม่แตกตื่น)* "ขอลองอีกครั้งที่มุมต่างกันครับ"

**Action:**
- ล้มอีก 1 ครั้งที่มุมต่างกัน
- ถ้ายังไม่ work → ตัดเข้า backup ทันที **อย่ายืนรอ**

---

### ❌ Scenario 4: Power Bank แบตหมดกลาง demo

**วิธีแก้:**
> "ขออภัยครับ ขอเปลี่ยนแบต — ขอโชว์เป็นวิดีโอแทน"

**Action:** ตัดเข้า backup ทันที (อย่าเสียเวลาเปลี่ยน)

## 🎤 Tips ตอนพูดจริง

1. **อย่าหันหลังให้ผู้ฟัง** — ยืนเฉียง 45° ทั้งคนเห็น และ ESP32 เห็นเรา
2. **พูดทุกอย่างที่ทำ** — ("ตอนนี้ผมจะเดิน...") เผื่อคนนั่งหลังมองไม่เห็นชัด
3. **ชี้เม้าส์ที่กราฟ** ตอนสัญญาณเปลี่ยน — direct attention ให้ถูกจุด
4. **ล้มเบาๆ ช้าๆ** — เพื่อโชว์ pre-fall, fall, post-fall ทั้งสาม phase ในกราฟ
5. **อย่าซ่อม live** — ถ้าหลุดให้ตัดเข้า backup ทันที เสียเวลา = เสียคนฟัง
6. **อย่ารับสาย / ตอบ noti** ระหว่าง demo
7. **พูดคำว่า "raw signal"** อย่างน้อย 1 ครั้ง — เน้นว่ายังไม่ใช่ model
