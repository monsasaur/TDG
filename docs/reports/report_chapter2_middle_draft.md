## ผู้สูงอายุและปัญหาการหกล้ม

ผู้สูงอายุเป็นกลุ่มประชากรที่มีความเสี่ยงต่อการบาดเจ็บจากการหกล้มมากกว่ากลุ่มวัยอื่น เนื่องจากการเปลี่ยนแปลงทางร่างกาย เช่น กล้ามเนื้ออ่อนแรง การทรงตัวลดลง การมองเห็นลดลง โรคประจำตัว และการใช้ยาบางประเภทที่อาจส่งผลต่อการเคลื่อนไหวหรือความรู้สึกตัว องค์การอนามัยโลกระบุว่าการหกล้มเป็นปัญหาสาธารณสุขที่สำคัญ โดยเป็นสาเหตุการเสียชีวิตจากการบาดเจ็บโดยไม่ตั้งใจอันดับต้น ๆ ของโลก และผู้สูงอายุเป็นกลุ่มที่ได้รับผลกระทบสูงจากการหกล้ม (World Health Organization, 2021)

ในบริบทของประเทศไทย จำนวนผู้สูงอายุเพิ่มขึ้นอย่างต่อเนื่องและเข้าสู่สังคมสูงวัยอย่างสมบูรณ์แล้ว สำนักงานสถิติแห่งชาติรายงานว่าในปี พ.ศ. 2567 ประเทศไทยมีประชากรอายุ 60 ปีขึ้นไปมากกว่า 14 ล้านคน และมีแนวโน้มที่ผู้สูงอายุบางส่วนอาศัยอยู่ลำพังหรืออยู่กับคู่สมรสสูงวัยมากขึ้น (สำนักงานสถิติแห่งชาติ, 2567) กรมควบคุมโรคยังระบุว่าผู้สูงอายุประมาณ 1 ใน 3 มีเหตุหกล้มทุกปี ซึ่งแสดงให้เห็นว่าระบบช่วยเฝ้าระวังและแจ้งเตือนเหตุการณ์หกล้มมีความจำเป็นต่อการดูแลผู้สูงอายุในบ้านและชุมชน (กรมควบคุมโรค, 2567)

## ระบบตรวจจับการล้ม

ระบบตรวจจับการล้มเป็นระบบที่ใช้ข้อมูลจากเซนเซอร์หรืออุปกรณ์ตรวจวัดเพื่อตรวจสอบว่าเกิดเหตุการณ์ที่มีลักษณะใกล้เคียงกับการล้มหรือไม่ แนวทางทั่วไปสามารถแบ่งได้เป็น 3 กลุ่ม ได้แก่ ระบบที่ใช้อุปกรณ์สวมใส่ ระบบที่ใช้กล้องหรือภาพวิดีโอ และระบบที่ไม่ต้องติดอุปกรณ์กับร่างกาย เช่น การใช้สัญญาณวิทยุหรือสัญญาณ WiFi ระบบที่ใช้อุปกรณ์สวมใส่มีข้อดีด้านการตรวจจับการเคลื่อนไหวเฉพาะบุคคล แต่มีข้อจำกัดหากผู้สูงอายุลืมสวมใส่หรือไม่สะดวกใช้งานต่อเนื่อง ส่วนระบบที่ใช้กล้องอาจตรวจจับเหตุการณ์ได้ชัดเจน แต่มีข้อจำกัดด้านความเป็นส่วนตัว มุมกล้อง และสภาพแสง

โครงงานนี้เลือกใช้แนวทางแบบไม่ต้องใช้กล้องและไม่ต้องให้อุปกรณ์ติดอยู่กับร่างกายผู้สูงอายุ โดยใช้สัญญาณ WiFi Channel State Information (CSI) เพื่อสังเกตการเปลี่ยนแปลงของสัญญาณที่เกิดจากการเคลื่อนไหวภายในพื้นที่ การเลือกแนวทางนี้สอดคล้องกับงานวิจัยที่ชี้ว่าการตรวจจับกิจกรรมมนุษย์ด้วย WiFi CSI สามารถนำไปใช้กับการตรวจจับการล้มและกิจกรรมภายในอาคารได้ โดยลดข้อจำกัดด้านความเป็นส่วนตัวเมื่อเทียบกับระบบที่ใช้ภาพจากกล้อง (Damodaran et al., 2020)

## Internet of Things

Internet of Things (IoT) หมายถึงแนวคิดการเชื่อมต่ออุปกรณ์ทางกายภาพเข้ากับเครือข่าย เพื่อให้อุปกรณ์สามารถเก็บข้อมูล สื่อสาร และทำงานร่วมกับระบบซอฟต์แวร์ได้ อุปกรณ์ IoT มักประกอบด้วยเซนเซอร์ หน่วยประมวลผลขนาดเล็ก โมดูลสื่อสาร และซอฟต์แวร์ควบคุมการทำงาน แนวคิด IoT ทำให้อุปกรณ์ในสภาพแวดล้อมจริงสามารถส่งข้อมูลเข้าสู่ระบบสารสนเทศ และทำให้ระบบสามารถตอบสนองต่อเหตุการณ์ที่เกิดขึ้นได้อย่างรวดเร็ว

ในโครงงานนี้ ESP32 ทำหน้าที่เป็นอุปกรณ์ IoT สำหรับสร้างและรับข้อมูล WiFi CSI จากสภาพแวดล้อมภายในอาคาร ข้อมูลที่ได้จะถูกนำไปประมวลผลต่อในบริการ Backend และ Machine Learning Service เพื่อจำแนกเหตุการณ์การล้ม เมื่อตรวจพบเหตุการณ์ที่เข้าข่ายการล้ม ระบบจะส่งข้อมูลต่อไปยังฐานข้อมูลและแอปพลิเคชันผู้ดูแล ดังนั้น IoT จึงเป็นส่วนสำคัญที่เชื่อมต่อระหว่างสภาพแวดล้อมจริงของผู้สูงอายุและระบบซอฟต์แวร์ที่ใช้แจ้งเตือน

## ESP32 และ ESP-IDF

ESP32 เป็นไมโครคอนโทรลเลอร์ที่รองรับการเชื่อมต่อ WiFi และ Bluetooth ในตัว เหมาะสำหรับการพัฒนาอุปกรณ์ IoT เพราะมีขนาดเล็ก ราคาไม่สูง และสามารถเขียนโปรแกรมเพื่อรับส่งข้อมูลผ่านเครือข่ายได้ ESP-IDF เป็น Framework หลักจาก Espressif สำหรับพัฒนาโปรแกรมบนตระกูล ESP32 โดยรองรับการตั้งค่า WiFi การจัดการ callback และการเรียกใช้ API ที่เกี่ยวข้องกับข้อมูล CSI

เอกสารของ Espressif ระบุว่าการใช้งาน WiFi CSI ต้องเปิดการตั้งค่า WiFi CSI ใน menuconfig กำหนด callback สำหรับรับ CSI ด้วย API ที่เกี่ยวข้อง กำหนดค่าการรับ CSI และเปิดใช้งาน CSI (Espressif Systems, 2026) ในโครงงานนี้ใช้ ESP32 จำนวน 2 ตัว โดยตัวหนึ่งทำหน้าที่เป็นตัวส่ง packet และอีกตัวทำหน้าที่เป็นตัวรับ CSI จากนั้นส่งข้อมูลผ่าน USB Serial ไปยังคอมพิวเตอร์สำหรับเก็บข้อมูลและทดสอบระบบ

## WiFi Channel State Information

Channel State Information (CSI) คือข้อมูลที่อธิบายสภาพของช่องสัญญาณไร้สายระหว่างตัวส่งและตัวรับในระบบ WiFi ข้อมูลดังกล่าวสะท้อนการเปลี่ยนแปลงของสัญญาณที่เกิดจากการสะท้อน การหักเห การดูดกลืน และการรบกวนจากวัตถุหรือมนุษย์ในพื้นที่ เมื่อมนุษย์เคลื่อนไหวภายในบริเวณที่มีสัญญาณ WiFi ลักษณะของ CSI จะเปลี่ยนแปลงตามรูปแบบการเคลื่อนไหว ทำให้สามารถนำข้อมูลดังกล่าวไปใช้วิเคราะห์กิจกรรม เช่น เดิน นั่ง ยืน หรือการล้มได้

งานวิจัยของ Damodaran et al. (2020) อธิบายว่า WiFi CSI สามารถใช้ในการรู้จำกิจกรรมมนุษย์และการตรวจจับการล้มได้ทั้งในสถานการณ์ Line-of-Sight และ Non-Line-of-Sight ซึ่งมีประโยชน์ต่อการดูแลผู้สูงอายุในสภาพแวดล้อมภายในอาคาร โครงงานนี้จึงนำ CSI มาแปลงเป็นคุณลักษณะจำนวน 416 ค่า โดยคำนวณจาก subcarrier และค่าสถิติต่าง ๆ เพื่อใช้เป็นข้อมูลนำเข้าสำหรับโมเดล Machine Learning

## Machine Learning

Machine Learning เป็นสาขาหนึ่งของปัญญาประดิษฐ์ที่ทำให้คอมพิวเตอร์เรียนรู้รูปแบบจากข้อมูลและนำรูปแบบดังกล่าวไปใช้ทำนายหรือจำแนกข้อมูลใหม่ได้ กระบวนการทั่วไปประกอบด้วยการรวบรวมข้อมูล การเตรียมข้อมูล การเลือกคุณลักษณะ การแบ่งข้อมูลสำหรับฝึกและทดสอบโมเดล การฝึกโมเดล และการประเมินผลลัพธ์ เมื่อใช้งานจริง โมเดลจะรับข้อมูลนำเข้าแล้วส่งผลลัพธ์เป็นค่าทำนายหรือค่าความมั่นใจ

ในโครงงานนี้ Machine Learning ใช้สำหรับจำแนกข้อมูล CSI ว่าเป็นเหตุการณ์การล้ม (fall) หรือไม่ใช่การล้ม (no_fall) ข้อมูล CSI จะถูกแปลงเป็น feature vector แล้วนำไปผ่านตัวปรับสเกลข้อมูลก่อนเข้าสู่โมเดล จากนั้นระบบจะได้ค่าความน่าจะเป็นหรือค่าความมั่นใจของการล้ม และนำไปตัดสินด้วยค่า threshold ที่กำหนดไว้ เพื่อให้ Backend API สามารถดำเนินการแจ้งเตือนได้อย่างเป็นระบบ

## Random Forest

Random Forest เป็นอัลกอริทึม Machine Learning ประเภท Ensemble Learning ที่สร้างจากต้นไม้ตัดสินใจหลายต้น แต่ละต้นเรียนรู้จากชุดข้อมูลย่อยและคุณลักษณะบางส่วน จากนั้นนำผลของแต่ละต้นมารวมกันเพื่อให้ได้ผลลัพธ์สุดท้าย วิธีนี้ช่วยเพิ่มความแม่นยำและลดปัญหา overfitting เมื่อเทียบกับการใช้ต้นไม้ตัดสินใจเพียงต้นเดียว Breiman (2001) อธิบายว่า Random Forest คือชุดของตัวจำแนกแบบต้นไม้หลายตัวที่ใช้การสุ่มและให้ต้นไม้แต่ละต้นลงคะแนนเพื่อเลือกคำตอบที่เหมาะสมที่สุด

Scikit-learn อธิบายว่า RandomForestClassifier เป็น meta estimator ที่สร้างตัวจำแนกแบบ Decision Tree หลายตัวบนชุดข้อมูลย่อย แล้วใช้การเฉลี่ยหรือการลงคะแนนเพื่อปรับปรุงความแม่นยำและควบคุม overfitting (Scikit-learn Developers, 2026) ในโครงงานนี้ ML Service ใช้โมเดล Random Forest สำหรับจำแนกข้อมูล CSI ที่มีจำนวนคุณลักษณะ 416 ค่า โดยโมเดลจะให้ผลลัพธ์เป็น fall หรือ no_fall พร้อมค่าความมั่นใจ เพื่อส่งกลับไปยัง Backend API

## REST API และ Express

Representational State Transfer (REST) เป็นรูปแบบสถาปัตยกรรมสำหรับระบบเครือข่ายที่ใช้แนวคิดทรัพยากร (resource) และการสื่อสารผ่าน HTTP Method เช่น GET, POST, PUT และ DELETE แนวคิด REST ทำให้ Client และ Server แยกหน้าที่กันชัดเจน โดย Client ส่งคำขอไปยัง endpoint ของ Server และ Server ตอบกลับด้วยข้อมูลที่มีรูปแบบกำหนดไว้ เช่น JSON (Fielding, 2000)

Express เป็น Web Framework สำหรับ Node.js ที่ใช้สร้าง API และจัดการเส้นทางของคำขอ HTTP ได้อย่างยืดหยุ่น เอกสารของ Express ระบุว่า route method เชื่อมโยงกับ HTTP method และ route path เพื่อกำหนด endpoint ที่ Client สามารถเรียกใช้งานได้ (Express, 2026) ในโครงงานนี้ Express API ทำหน้าที่รับข้อมูลจากอุปกรณ์หรือ demo endpoint เรียกใช้ ML Service บันทึกเหตุการณ์ลงฐานข้อมูล ส่ง Push Notification และรับคำสั่งยืนยันการรับทราบจากแอปพลิเคชันผู้ดูแล

## FastAPI

FastAPI เป็น Web Framework สำหรับภาษา Python ที่ใช้สร้าง API ประสิทธิภาพสูง โดยอาศัย type hints มาตรฐานของ Python และรองรับการสร้างเอกสาร API อัตโนมัติผ่านมาตรฐาน OpenAPI และ JSON Schema (FastAPI, 2026) คุณสมบัติดังกล่าวเหมาะกับการพัฒนา Machine Learning Service เพราะสามารถรับข้อมูล JSON จาก Backend API ตรวจสอบรูปแบบข้อมูล และส่งผลลัพธ์กลับได้อย่างชัดเจน

ในโครงงานนี้ FastAPI ใช้สร้าง endpoint `/predict` สำหรับรับข้อมูล feature จาก Express API แล้วเรียกใช้ฟังก์ชันประมวลผลโมเดลในไฟล์ `predict.py` ผลลัพธ์ที่ส่งกลับประกอบด้วย prediction, confidence และ is_fall ซึ่งทำให้ Backend API สามารถตัดสินใจต่อได้ว่าจะบันทึกเหตุการณ์และแจ้งเตือนผู้ดูแลหรือไม่

## ฐานข้อมูล Supabase และ PostgreSQL

ฐานข้อมูลเป็นส่วนที่ใช้จัดเก็บข้อมูลอย่างเป็นระบบ เพื่อให้ระบบสามารถเรียกดู แก้ไข และติดตามสถานะของข้อมูลได้ Supabase เป็นแพลตฟอร์ม Backend as a Service ที่ให้บริการฐานข้อมูล PostgreSQL พร้อมความสามารถด้าน Realtime, Auth, Storage และ Client Libraries สำหรับหลายภาษา เอกสารของ Supabase ระบุว่าแต่ละโปรเจคมีฐานข้อมูล Postgres พร้อมความสามารถด้าน Realtime และเครื่องมือที่เกี่ยวข้อง (Supabase, 2026)

ในโครงงานนี้ Supabase ใช้จัดเก็บตาราง `fall_events` และ `push_tokens` ตาราง `fall_events` เก็บข้อมูลเหตุการณ์การล้ม เช่น device_id, timestamp, location, is_fall, confidence, acknowledged และ escalated ส่วนตาราง `push_tokens` ใช้เก็บ token ของแอปผู้ดูแลสำหรับส่ง Push Notification การจัดเก็บข้อมูลในฐานข้อมูลทำให้ระบบสามารถแสดงประวัติการแจ้งเตือน ตรวจสอบสถานะการตอบรับ และนำข้อมูลไปวิเคราะห์เพื่อปรับปรุงระบบในอนาคตได้

## React Native และ Expo

React Native เป็น Framework สำหรับพัฒนาแอปพลิเคชันบนอุปกรณ์เคลื่อนที่ด้วย JavaScript และ React โดยสามารถสร้างส่วนติดต่อผู้ใช้ที่ทำงานบนระบบ Android และ iOS ได้ เอกสาร React Native ระบุว่าผู้พัฒนาควรมีพื้นฐาน JavaScript และสามารถเรียนรู้แนวคิด Native Components, React และการพัฒนาแอปข้ามแพลตฟอร์มจากเอกสารทางการได้ (Meta Open Source, 2026)

Expo เป็นเครื่องมือและแพลตฟอร์มที่ช่วยให้การพัฒนา React Native สะดวกขึ้น โดยสนับสนุนการจัดการโปรเจค การทดสอบแอป และการใช้บริการต่าง ๆ เช่น Notifications ในโครงงานนี้แอปพลิเคชัน Middle พัฒนาด้วย React Native และ Expo เพื่อให้ผู้ดูแลสามารถดูรายการแจ้งเตือน ตรวจสอบสถานะเหตุการณ์ กดยืนยันการรับทราบ และจัดการข้อมูลพื้นฐานของบ้านหรืออุปกรณ์ได้

## Push Notification และระบบแจ้งเตือนฉุกเฉิน

Push Notification เป็นกลไกการแจ้งเตือนจาก Server ไปยังแอปพลิเคชันบนอุปกรณ์ผู้ใช้ แม้ผู้ใช้ไม่ได้เปิดแอปอยู่ก็ตาม เอกสาร Expo ระบุว่า Expo Push Notification Service ช่วยลดความซับซ้อนในการสื่อสารกับ Firebase Cloud Messaging (FCM) และ Apple Push Notification Service (APNs) ทำให้สามารถจัดการการแจ้งเตือน Android และ iOS ด้วยแนวทางเดียวกันได้ (Expo, 2025)

ในโครงงานนี้เมื่อ Backend API ตรวจพบเหตุการณ์การล้ม ระบบจะส่ง Push Notification ไปยังแอปพลิเคชัน Middle ของผู้ดูแลก่อน จากนั้นจะเริ่มนับเวลารอการตอบรับ หากผู้ดูแลกดยืนยันภายในเวลาที่กำหนด ระบบจะยุติการแจ้งเตือนต่อเนื่อง แต่หากไม่มีการตอบรับ ระบบจะยกระดับการแจ้งเตือนผ่าน Twilio Voice Call โดย Twilio ระบุว่า Voice API สามารถใช้สร้างและจัดการสายโทรศัพท์ผ่าน REST API รวมถึงการโทรออกไปยังหมายเลขโทรศัพท์ภายนอกได้ (Twilio, 2026)

## สถาปัตยกรรมของระบบที่เกี่ยวข้องกับทฤษฎี

จากทฤษฎีและเทคโนโลยีที่กล่าวมาข้างต้น โครงงานนี้สามารถสรุปภาพรวมได้เป็นลำดับการทำงานดังนี้ ESP32 เก็บข้อมูล WiFi CSI จากสภาพแวดล้อม ข้อมูลถูกแปลงเป็นคุณลักษณะและส่งต่อไปยัง Express API จากนั้น Express API เรียกใช้ FastAPI ML Service เพื่อจำแนกเหตุการณ์ หากโมเดลตรวจพบการล้ม ระบบจะบันทึกข้อมูลลง Supabase ส่ง Push Notification ไปยังแอป Middle และรอการตอบรับจากผู้ดูแล หากไม่มีการตอบรับภายในเวลาที่กำหนด ระบบจะใช้ Twilio Voice Call เพื่อแจ้งเตือนในระดับถัดไป
