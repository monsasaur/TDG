**สถานะ:** พร้อมให้เริ่ม · ฝั่ง firmware และ service layer ทำเสร็จแล้ว รออันนี้อย่างเดียว

## สรุปสั้น (อ่านแค่นี้ก็เริ่มงานได้)

**ทำอะไร:** สร้างหน้าจอใหม่ 1 หน้า ให้ผู้ใช้กรอกหรือสแกน "รหัสจับคู่อุปกรณ์" ที่พิมพ์อยู่บนกล่อง

**ทำไม:** flow ตั้งค่าอุปกรณ์ผ่าน BLE ขาดหน้านี้จุดเดียว แล้วใช้งานไม่ได้ทั้งเส้น

**แทรกตรงไหน:**
```
scan-devices  →  [ หน้าใหม่ ]  →  connect-device  →  wifi-password  →  device-setup
```

**ต้องแก้ 2 ไฟล์:**
1. สร้าง `app/device-pairing-code.tsx` (ไฟล์ใหม่)
2. แก้ `app/scan-devices.tsx` ตอนกดเลือกอุปกรณ์ ให้ไปหน้าใหม่แทน `connect-device`

**หน้าใหม่ทำแค่:** รับรหัส → ส่งต่อเป็น query param
```
/connect-device?device=ESP-0001A&pop=<รหัส>
```
ไม่ต้องตรวจรหัสเอง ไม่ต้องเรียก API อุปกรณ์เป็นคนตัดสินว่าถูกผิด

**ไม่ต้องแตะ:** `lib/provisioning.ts` · `connect-device.tsx` · component ต่าง ๆ (มีครบแล้ว)

**❌ ห้ามเอามาใช้ซ้ำ:** `enter-code.tsx` และ `scan-qr.tsx` — ชื่อเหมือนแต่เป็นรหัสเชิญเข้าบ้าน คนละเรื่อง

**⚠️ กับดักเดียวที่ต้องระวัง:** อย่าใส่ `autoCapitalize="characters"` (`enter-code.tsx` ใส่ไว้)
รหัสแยกตัวพิมพ์เล็กใหญ่ — ถ้าแปลงเป็นตัวใหญ่หมดจะจับคู่ไม่ติด โดยที่ผู้ใช้เห็นว่าพิมพ์ถูกแล้ว

**ใช้เวลาประมาณ:** ครึ่งวัน

## 1. ทำไมต้องมี

flow ตั้งค่าอุปกรณ์ผ่าน BLE **ขาดหน้าจอนี้จุดเดียว** แล้วทั้ง flow ใช้งานไม่ได้

firmware ตั้งไว้ที่ Security 1 ซึ่ง**บังคับให้ต้องมีรหัสจับคู่ (Proof of Possession)**
ถ้าแอปเรียก `connect()` โดยไม่ส่งรหัส อุปกรณ์จะปฏิเสธทุกครั้ง

รหัสนี้กันคนข้างบ้านมาตั้งค่าอุปกรณ์เรา — เป็นสตริงสุ่มยาวที่พิมพ์อยู่บนกล่อง/ตัวเครื่อง

```
สแกนเจออุปกรณ์  →  [ ❌ หน้าที่ขาด: กรอกรหัส ]  →  เลือก WiFi  →  ใส่รหัส WiFi  →  เสร็จ
scan-devices                                        connect-device   wifi-password   device-setup
```

## 2. ⚠️ อย่าเอาหน้าที่มีอยู่มาใช้ซ้ำ

มีสองหน้าที่ดูเหมือนใช่แต่**คนละเรื่องกันสนิท** — อย่าแก้สองไฟล์นี้

| ไฟล์ | จริง ๆ คืออะไร |
|---|---|
| `app/enter-code.tsx` | "กรอกรหัสบ้าน" — รหัสเชิญเข้าร่วมบ้านของคนอื่น ไม่เกี่ยวกับอุปกรณ์ |
| `app/scan-qr.tsx` | QR เชิญเข้าบ้าน เรียกจาก `houses.tsx` ไม่เกี่ยวกับอุปกรณ์ |

> หมายเหตุแยกต่างหาก: ทั้งสองหน้านี้ยังเป็น mock ที่ **ปฏิเสธทุกค่า**

> ไม่ใช่งานในใบนี้ แต่ควรมีใบงานแยกไปแก้

**สร้างไฟล์ใหม่** เช่น `app/device-pairing-code.tsx`

## 3. สิ่งที่ต้องทำ

### 3.1 ตำแหน่งใน flow

แทรกระหว่าง `scan-devices` กับ `connect-device`

**แก้ `app/scan-devices.tsx`** — ตอนนี้กดเลือกอุปกรณ์แล้วไป `connect-device` ตรง ๆ
ให้เปลี่ยนไปหน้าใหม่แทน (บรรทัด ~206 `selectDevice`)

```
เดิม   /connect-device?device=ESP-0001A
ใหม่   /device-pairing-code?device=ESP-0001A
```

**หน้าใหม่ส่งต่อ** เมื่อได้รหัสแล้ว
```
/connect-device?device=ESP-0001A&pop=<รหัสที่ได้>
```

`connect-device.tsx` **ไม่ต้องแก้** — รับ `pop` ไว้อยู่แล้ว (บรรทัด 19-23) และส่งเข้า
`connect(device, pop)` ให้เอง

### 3.2 หน้าตา

ใช้ component ที่มีอยู่แล้วทั้งหมด ไม่ต้องสร้างใหม่

| ส่วน | ใช้ component |
|---|---|
| หัวข้อ + ปุ่มย้อนกลับ | `PageHeader` |
| ช่องกรอกรหัส | `LabeledTextField` |
| ปุ่มยืนยัน | `PrimaryButton` |
| กรอบสแกน QR | `QrScannerFrame` + `CameraView` จาก `expo-camera` |
| แจ้ง error | `ConfirmModal` |

**ต้องมี 2 ทาง** ให้ผู้ใช้เลือก — สแกน QR บนกล่อง หรือพิมพ์เอง
(บางกล่องพิมพ์ QR เบลอ / กล้องเสีย / แสงไม่พอ ต้องมีทางสำรองเสมอ)

ข้อความแนะนำที่ควรมี: *"รหัสอยู่บนกล่องหรือใต้ตัวเครื่อง"*

### 3.3 พฤติกรรม

| กรณี | ต้องทำอะไร |
|---|---|
| ยังไม่กรอกอะไร | ปุ่มยืนยันเป็นสีเทา กดไม่ได้ |
| สแกน QR ได้ | เอาค่าที่อ่านได้ไปใส่ในช่องเลย ให้ผู้ใช้เห็นก่อนกดยืนยัน (อย่าไปหน้าถัดไปเอง — ให้เขาตรวจก่อน) |
| กดยืนยัน | ไป `/connect-device` พร้อม `pop` |
| กดย้อนกลับ | เรียก `disconnect()` จาก `lib/provisioning` ก่อน ไม่งั้น BLE ค้างเชื่อมต่อ |

**อย่าตรวจรหัสเองในหน้านี้** — ส่งไปเลย ตัวอุปกรณ์เป็นคนตัดสินว่าถูกหรือผิด
ถ้าผิด `connect-device` จะแสดง error ให้เองอยู่แล้ว (ดูข้อ 5)

## 4. สัญญากับ service layer

`lib/provisioning.ts` **ทำเสร็จแล้ว ไม่ต้องแก้** — หน้าใหม่แค่ส่ง `pop` ผ่าน route param

```ts
// connect-device.tsx เรียกให้เองอยู่แล้ว
await connect(device, pop)
```

ถ้าจำเป็นต้องเรียกตรง:
```ts
import { connect, disconnect, errorMessage, isMock } from "../lib/provisioning";
```

`isMock` = `true` เมื่อรันบน Expo Go / เว็บ (ไม่มี native module) —
ใช้แสดงป้ายบอกว่าอยู่โหมดจำลอง แบบเดียวกับที่ `scan-devices.tsx` ทำ

---

## 5. ข้อความ error — มีให้แล้ว อย่าเขียนใหม่

`errorMessage()` ใน `lib/provisioning.ts` แปลง error จาก native เป็นภาษาไทยให้แล้ว
`connect-device.tsx` เรียกใช้อยู่แล้ว

| อุปกรณ์ตอบว่า | ผู้ใช้จะเห็น |
|---|---|
| PoP ผิด | รหัสอุปกรณ์ไม่ถูกต้อง ลองสแกน QR บนกล่องอีกครั้ง |
| หมดเวลา | หมดเวลาเชื่อมต่อ ลองใหม่อีกครั้งโดยให้มือถืออยู่ใกล้อุปกรณ์ |
| บลูทูธมีปัญหา | เชื่อมต่อบลูทูธไม่ได้ ตรวจสอบว่าเปิดบลูทูธอยู่ |

**ที่ต้องทำเพิ่ม:** เมื่อ `connect-device` แสดง error ว่ารหัสผิด ควรมีปุ่มให้ย้อนกลับมา
หน้ากรอกรหัสได้สะดวก ไม่ใช่ให้ผู้ใช้กด back เอง

## 6. ข้อกำหนดของรหัส

| หัวข้อ | ค่า |
|---|---|
| ตัวอย่าง | `ESP-0001A` คือ **ชื่ออุปกรณ์** ไม่ใช่รหัส · รหัสเป็นสตริงสุ่มยาวคนละตัว |
| ความยาว | ยาวและสุ่ม ไม่ใช่ PIN 4 หลัก (ดูเหตุผลข้อ 8) |
| ตัวพิมพ์ | **แยกตัวพิมพ์เล็กใหญ่** — อย่าใส่ `autoCapitalize="characters"` เหมือน `enter-code.tsx` |
| ช่องว่าง | `trim()` หัวท้ายก่อนส่ง (คนคัดลอกมามักติดช่องว่าง) แต่ห้ามแก้ตรงกลาง |

> ⚠️ จุดที่พลาดง่ายที่สุด: `enter-code.tsx` ใช้ `autoCapitalize="characters"`
> ถ้าลอกโค้ดนั้นมา รหัสที่มีตัวพิมพ์เล็กจะถูกแปลงเป็นตัวใหญ่หมด แล้วจับคู่ไม่ติด
> โดยที่ผู้ใช้เห็นว่าพิมพ์ถูกแล้ว

## 7. เกณฑ์ว่างานเสร็จ

- [ ] กรอกรหัสด้วยมือแล้วไปหน้าถัดไปพร้อม `pop` ใน URL
- [ ] สแกน QR แล้วค่าขึ้นในช่อง ผู้ใช้ยืนยันเองอีกที
- [ ] ปุ่มยืนยันกดไม่ได้เมื่อช่องว่าง
- [ ] กดย้อนกลับแล้วเรียก `disconnect()`
- [ ] รหัสที่มีตัวพิมพ์เล็กไม่ถูกแปลงเป็นตัวใหญ่
- [ ] ช่องว่างหัวท้ายถูกตัด
- [ ] ไม่มีกล้อง / ไม่ให้สิทธิ์กล้อง → ยังพิมพ์เองได้
- [ ] รันบน Expo Go แล้วไม่ crash (ขึ้นป้ายโหมดจำลอง)
- [ ] `npx tsc --noEmit` ไม่มี error ใหม่

**ทดสอบกับบอร์ดจริงยังทำไม่ได้ตอนนี้** — firmware ยังไม่เคย build (ดูข้อ 9)
ทดสอบเท่าที่ทำได้: flow เดินได้ครบ, ค่า `pop` ส่งถึงปลายทาง, error แสดงถูก

## 8. บริบทเพิ่มเติม (ไม่ต้องทำ แต่ควรรู้)

**ทำไมรหัสต้องยาว** — firmware ใช้ Security 1 ซึ่งเอารหัสนี้ไปคำนวณ key
ถ้ารหัสสั้นหรือเดาง่าย คนที่ดักจับสัญญาณ BLE ตอนจับคู่ไว้ เอาไป brute force offline ได้
เพราะฉะนั้นถ้ามีคนเสนอให้เปลี่ยนเป็น PIN 4 หลักเพื่อความสะดวก **ต้องปฏิเสธ**

**ค่านี้ตั้งที่ firmware** (`CONFIG_PROV_POP` ใน menuconfig) ฝั่งแอปแค่ส่งต่อ
ไม่ต้องเก็บ ไม่ต้องตรวจ
