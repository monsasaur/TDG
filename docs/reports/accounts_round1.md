## เปิดใช้ — ทำตามลำดับ

> ⚠️ **อย่ารัน `accounts.sql` ก่อนทดสอบสด 13 พ.ย.** พอเปิด RLS แล้วแอปที่ไม่ได้ login จะไม่เห็นอะไรเลย

**1. เปิด Phone provider ใน Supabase**
Authentication → Sign In / Providers → Phone → เปิด แล้ว **ปิด "Enable phone confirmations"**
(แอปรอบนี้ไม่มีขั้นกรอก OTP — ถ้าเปิดไว้ สมัครแล้วจะขึ้นว่า "ระบบยังเปิดการยืนยันเบอร์ทาง SMS อยู่")
ถ้าหน้านั้นบังคับให้เลือก SMS provider ก่อนบันทึก ใส่ค่า Twilio ที่มีอยู่ได้ — ปิดการยืนยันแล้วตอนสมัครจะไม่ส่ง SMS

**2. Express ต้องใช้ service_role key**
`express_api/.env` → `SUPABASE_URL` + `SUPABASE_KEY` = service_role (Project Settings → API) ไม่ใช่ anon
หลังเปิด RLS คีย์อื่นเขียน `fall_events` / `alerts` ไม่ได้ (ไม่มี error ชัด ๆ เหตุการณ์แค่ไม่ขึ้นในแอป)
`node scripts/check_live_setup.js` ขึ้น ❌ ถ้ารัน accounts.sql แล้วแต่คีย์ไม่ใช่ service_role

**3. รัน `schema.sql` → ลงแอปเวอร์ชันนี้ → สมัครบัญชีแรก (คนที่จะเป็นเจ้าของบ้านเดิม)**

**4. รัน `accounts.sql` → รันคำสั่งท้ายไฟล์ครั้งเดียว** (ใส่เบอร์บัญชีแรกแบบ `66812345678`)
ยกบ้านที่มีอยู่ก่อนเปิดระบบบัญชีให้เป็นของบัญชีนั้น — ถ้าไม่รัน บ้านเดิมจะไม่มีใครมองเห็น
ทั้งสองไฟล์รันซ้ำได้

### ต้อง build dev client ใหม่ 1 ครั้ง

`@react-native-async-storage/async-storage` เป็น native module — dev client ที่ build ก่อนวันนี้ไม่มี
แอปไม่พัง (ถอยไปเก็บ session ในหน่วยความจำ + เตือนใน log) **แต่ปิดแอปแล้วต้อง login ใหม่ทุกครั้ง** จนกว่าจะ build ใหม่
ไลบรารี QR (`react-native-qrcode-svg`) เป็น JS ล้วน ไม่ต้อง build ใหม่

## รอบ 2 — 13 พ.ย. 2026: push เฉพาะสมาชิกบ้าน + กดรับทราบต้องยืนยันตัวตน

ทุกข้อทำงานแบบเดิมจนกว่าจะรัน `accounts.sql` (Express เช็คว่ามีตาราง `house_members` ไหม · จำผล 60 วิ)

| เรื่อง | ก่อนรัน accounts.sql | หลังรัน |
|---|---|---|
| ใครได้ push ตอนตรวจพบการล้ม | ทุกเครื่องที่ลงทะเบียน (แบบเดิม) | เฉพาะเครื่องที่ login เป็นสมาชิกบ้านของอุปกรณ์นั้น · อุปกรณ์ไม่ได้ผูกกับบ้าน = ไม่ส่งให้ใคร · **การโทรฉุกเฉินยังทำงานตามเดิมทุกกรณี** |
| `POST /alert/ack` | ใครมี x-api-key ก็กดได้ · ส่ง token มาก็ใช้ชื่อจากบัญชี | ต้องส่ง `Authorization: Bearer <access token>` + เป็นสมาชิกบ้านของอุปกรณ์ ไม่งั้น 401 / 403 · ชื่อ "รับทราบโดย" มาจากบัญชี ไม่เชื่อชื่อที่แอปส่ง |
| `POST /push/register` | ผูกเครื่องกับบัญชีถ้าส่ง token มา (คอลัมน์ยังไม่มีก็ลงทะเบียนแบบเดิมได้) | ไม่ส่ง token = ปลดการผูก (หลังออกจากระบบ) |
| `GET /push/tokens` | ย้ายไปใช้ **DEMO_API_KEY** ทันที — คืน token ทุกเครื่อง ใครได้ไปก็ยิง push ปลอมได้ | เหมือนกัน |

**ทำไมต้องกันการกดรับทราบ:** คีย์ของแอปฝังใน APK และ `GET /events` คืนเหตุการณ์ทุกบ้าน —
ใครแกะคีย์ได้ก็ดึง id แล้วกดรับทราบแทนบ้านอื่น = ยกเลิกการโทรฉุกเฉินของคนอื่นได้

แอป: แนบ token อัตโนมัติ (`lib/api.ts` → `withUserToken`) · ลงทะเบียน push ใหม่ทุกครั้งที่ login / ออกจากระบบ (`app/_layout.tsx` → `PushSetup`)
· ถูกปฏิเสธ (401/403) ขึ้นข้อความว่าต้องเข้าสู่ระบบด้วยบัญชีที่เป็นสมาชิกบ้านนี้ และย้อนหน้าจอกลับ

ฐานข้อมูล: `accounts.sql` เพิ่ม `push_tokens.user_id` (→ `auth.users` · ลบบัญชีแล้วเป็น null ไม่ลบแถว)

⚠️ **หลังรัน accounts.sql ปุ่ม demo ต้องใช้อุปกรณ์ที่ผูกกับบ้านแล้ว** — `POST /demo/fire` ค่าเริ่มต้นคือ `esp32-demo-01`
ซึ่งไม่ได้อยู่ในตาราง `devices` → จะไม่มี push · ส่ง `{"device_id": "ESP-B96AB8"}` (หรือรหัสที่ลงทะเบียนแล้ว) และ curl ที่กดรับทราบต้องแนบ token ด้วย

`GET /events` / `/events/falls` ย้ายไป **DEMO_API_KEY** แล้วเช่นกัน (คืนเหตุการณ์ทุกบ้าน · แอปไม่ได้ใช้ — อ่านจากตาราง `alerts` ผ่าน RLS · ลบ `fetchFallEvents` ที่ไม่มีใครเรียกออกจาก `lib/api.ts`)
