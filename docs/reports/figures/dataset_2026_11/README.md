# กราฟสำหรับสไลด์ — dataset 2026-11 (5 คน · 801 ไฟล์)

สร้างใหม่ได้ทุกเมื่อ:

```bash
cd fall_detection_backend/ml_service && source venv/bin/activate
python experiments/presentation_numbers.py      # คำนวณตัวเลขทั้งหมด → numbers.json + dashboard_data.json (~6 นาที)
python3 experiments/make_figures.py             # วาด PNG (python3 ของเครื่อง · venv ไม่มี matplotlib)
```

ทุกรูป 2000×1125 px (16:9) พื้นขาว · ตัวเลขทุกตัวอยู่ใน `numbers.json` · หน้าเว็บสรุปผล (artifact) ใช้ `dashboard_data.json`

## ตัวเลขหลักที่ใช้พูด

- **unseen 72.9% balanced accuracy · AUC 0.78** — เดาสุ่มได้ 50% (สลับ label 20 ครั้ง ได้สูงสุด 54.5%)
- จับล้มได้ 73% · แจ้งผิด 27% (threshold 0.5)
- ชุดแรกแบบ ideal 95.6% (accuracy)

## ต้องพูดคู่กันเสมอ

- วัดแบบ "รู้จังหวะเหตุการณ์แล้ว" (กรอบอยู่ที่จุดมาร์ค) — การใช้งานจริงไม่มีมาร์ค ต้องเลื่อนกรอบไปเรื่อย ๆ · ผลแบบนั้นอยู่ใน `docs/reports/live_test_rf_v2.md`
- ห้องเดียว ตำแหน่งวางบอร์ดเดียว — RSSI ที่ขึ้นหลังล้มขึ้นกับตำแหน่งบอร์ด ห้องอื่นอาจไม่เหมือนกัน
- ชุดแรกวัดเป็น accuracy ชุดใหม่วัดเป็น balanced accuracy (ข้อมูลเกือบสมดุลทั้งคู่)

## ทำไม unseen ต่ำกว่าชุดแรก

- unseen ยากกว่า ideal มาก: ideal ทดสอบกับคนเดิม ส่วน unseen ทดสอบกับคนที่ไม่ได้ใช้เทรนเลย
- ชุดใหม่ถ้าทดสอบแบบ ideal (seen · สุ่มแบ่งไฟล์ปนทุกคน) ได้ 74.1% ใกล้กับ unseen
- ชุดแรก 95.6% ส่วนใหญ่มาจากการเก็บท่าล้มทั้งหมดก่อนแล้วค่อยเก็บท่าไม่ล้ม โมเดลจึงแยกช่วงเวลาเก็บได้ ถ้าใช้เฉพาะ feature การเคลื่อนไหวเหลือ 72.6% (`docs/reports/data_quality_audit_2026-09.md`) · ชุดใหม่แก้เรื่องนี้แล้วด้วยการเก็บสลับกันใน session เดียว
- ลิงก์รอบนี้ noise สูงกว่าชุดแรกหลายเท่า — แก้ลิงก์คือขั้นต่อไป
