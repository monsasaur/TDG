# ทดสอบสด rf_v2_event — ตรวจจับการล้มแบบดูต่อเนื่อง

เตรียมไว้ 2026-11-11 · ทำในห้องเดิม จุดวางบอร์ดเดิม (กล่องสูง 60 ซม. ตรงข้ามกันราว 3 ม.)

## ทำไมต้องทดสอบสด

| วัดแบบไหน | จับล้มได้ | แจ้งผิดตอนกิจวัตร | ที่มา |
|---|---:|---:|---|
| รู้จังหวะเหตุการณ์ (กรอบอยู่ที่มาร์ค) | 72.9% balanced accuracy | — | `experiments/event_features.py` |
| เลื่อนกรอบทุก 0.25 วิ บนไฟล์ที่เก็บไว้ · threshold 0.4 · ยืนยัน 5 กรอบ (มี feature "นิ่งหลังเหตุการณ์") | 43% | ~4 ครั้ง/ชม. | `experiments/streaming_eval.py` · `models/report_rf_v2_event.json` |

ตัวเลขแถวสองประเมินจากไฟล์ยาวแค่ 7–9 วิ (กิจวัตรรวมราว 16 นาที) และไฟล์จบราว 2 วิหลังล้ม
ตอนใช้งานจริงคนนอนอยู่ที่พื้นต่อ การยืนยัน 5 กรอบน่าจะทันมากขึ้น ส่วนการเดินนาน ๆ อาจแจ้งผิดมากขึ้น
ทั้งสองอย่างรู้ได้จากการทดสอบสดเท่านั้น

ที่รู้แล้ว: ยืนนิ่งกับห้องว่างแทบไม่แจ้ง · แจ้งผิดเกือบทั้งหมดมาจากตอนเดิน · นอนลงบนพื้นโดนแจ้งราว 1 ใน 3

## เตรียม

1. ปิด `collect_web.py` (Ctrl-C) — พอร์ต USB ใช้ได้ทีละโปรแกรม
2. บอร์ดวางที่เดิม · #1 เสียบ USB กับแมค · #2 เสียบไฟ · อุ่นบอร์ด 10–15 นาที
3. เบาะรองสำหรับล้ม · คนกดนั่งนิ่ง ๆ ระหว่างทดสอบ

## ให้เหตุการณ์ขึ้นในแอป (ข้ามได้ — ไม่ทำก็ทดสอบได้ แต่เห็นทาง push อย่างเดียว)

ตรวจ 2026-11-12: ตอนนี้เหตุการณ์จากการทดสอบ**จะไม่โผล่ในรายการแจ้งเตือนของแอป** และกดรับทราบจากรายการไม่ได้ เพราะขาด 3 อย่าง

1. **รัน `schema.sql` บนฐานข้อมูลจริง** — Supabase Dashboard → SQL Editor → วางทั้งไฟล์
   `fall_detection_backend/supabase/schema.sql` → Run (ทุกคำสั่งเป็น IF NOT EXISTS รันซ้ำได้)
   ขาดข้อนี้จะไม่มีคอลัมน์ `alerts.fall_event_id` → Express สร้างแถวในแอปไม่ได้
2. **ให้ Express ต่อ Supabase** — เพิ่มใน `express_api/.env` (ไฟล์นี้ gitignore อยู่แล้ว) แล้วรีสตาร์ต Express
   - `SUPABASE_URL` = URL เดียวกับแอป (`data/supabaseClient.ts`)
   - `SUPABASE_KEY` = service_role key จาก Dashboard → Project Settings → API (คีย์ลับ ห้ามใส่ในแอป)
   ไม่ตั้ง = Express เก็บเหตุการณ์ในหน่วยความจำ ไม่ลงฐานข้อมูล รีสตาร์ตแล้วหาย
3. **ลงทะเบียนบอร์ดเข้าบ้าน** — ตาราง `devices` ตอนนี้มีแค่ ESP-0001A–0004D (ข้อมูลตัวอย่าง)
   บอร์ดรัน firmware โหมดเก็บข้อมูล จับคู่ผ่านแอปไม่ได้ → เพิ่มด้วย SQL Editor:
   ```sql
   INSERT INTO devices (id, house_id, name, code, wifi_ssid, status)
   VALUES ('d-b96ab8', 'h1', 'บอร์ดทดสอบ', 'ESP-B96AB8', 'myssid', 'connected');  -- h1 = บ้านแม่
   ```

เช็คก่อนเริ่ม:
1. `cd fall_detection_backend/express_api && node scripts/check_live_setup.js` — ต้องไม่มี ❌ (อ่านอย่างเดียว ไม่เขียนอะไร)
2. ยิง `POST /api/v1/demo/fire` ด้วย `{"device_id":"ESP-B96AB8"}` → ภายใน 10 วิ ต้องขึ้นการ์ดในแอปใต้บ้านแม่
   กดรับทราบแล้ว log ของ Express ต้องขึ้น `Caregiver acknowledged ... escalation cancelled` และไม่โทรออก

## ⚠️ สองเรื่องที่เจอตอนเช็คเครื่อง (2026-11-12)

- **พอร์ต 8000 มีโปรแกรมของโปรเจกต์อื่นจองอยู่** (ตอบ `/health` เป็นข้อมูล merchants) — uvicorn จะเปิดไม่ขึ้น
  ปิดโปรแกรมนั้นก่อน (`lsof -iTCP:8000 -sTCP:LISTEN` ดูว่าตัวไหน) หรือรัน ML service ที่ `--port 8001`
  แล้วรัน Express ด้วย `ML_SERVICE_URL=http://localhost:8001` นำหน้าคำสั่ง
- **`.env` ตั้ง `ACK_TIMEOUT_SECONDS=5`** (เหลือจากการทดสอบ 13 ต.ค.) = โทรฉุกเฉินหลังตรวจพบ 5 วิ กดรับทราบไม่ทัน
  คำสั่งข้างล่างใส่ `ACK_TIMEOUT_SECONDS=60` ไว้แล้ว — ค่าบนบรรทัดคำสั่งชนะค่าใน `.env`

## เปิด 3 terminal

```bash
# 1) ML service — ต้องเป็น rf_v2_event เพราะ Express จะถามซ้ำตอนบันทึกเหตุการณ์
cd fall_detection_backend/ml_service && source venv/bin/activate
FALL_MODEL=rf_v2_event uvicorn app.main:app --port 8000
#    เช็ค: curl localhost:8000/health → model_version rf_v2_event · n_features 28

# 2) Express — ช่วงทดสอบ: รอกดรับทราบ 60 วิ · กันแจ้งซ้ำแค่ 20 วิ · ไม่โทรจริง (ถ่ายวิดีโอค่อยเอา TWILIO_MODE ออก)
cd fall_detection_backend/express_api
ACK_TIMEOUT_SECONDS=60 COOLDOWN_SECONDS=20 TWILIO_MODE=fake npm run dev

# 3) ตัวตรวจจับสด
cd fall_detection_backend/ml_service && source venv/bin/activate
python data_collection/fall_monitor.py --dry-run                          # รอบแรก: ดูคะแนนอย่างเดียว
python data_collection/fall_monitor.py --env-file ../express_api/.env     # ส่งเข้า Express จริง
python data_collection/fall_monitor.py --env-file ../express_api/.env --stay-still 3   # + กฎล้มแล้วนิ่ง 3 วิ (แนะนำ)
#    ปรับได้: --threshold 0.3 (จับมากขึ้น แจ้งผิดมากขึ้น) · --confirm 4 · device_id ค่าเริ่มต้น ESP-B96AB8 (ต้องมีใน devices.code ถึงจะขึ้นในแอป)
```

ทุกกรอบถูกบันทึกที่ `ml_service/data/realtime/monitor_<เวลา>.csv` (คะแนน · จำนวนกรอบติดกัน · แจ้ง)

**กฎ "ล้มแล้วนิ่ง" (`--stay-still 3`):** ตรวจพบแล้วยังไม่แจ้งทันที รอดู 3 วิว่านิ่งอยู่ที่พื้นไหม
(นิ่ง ≥ 80% ของช่วง · เกณฑ์มาจากข้อมูล: 90% ของการล้มผ่าน ส่วนตอนเดินผ่านแค่ 37% ต่อกรอบ)
ถ้าขยับต่อหรือลุก = ไม่แจ้ง · แจ้งช้าลงเป็นราว 5.3 วิหลังตัวถึงพื้น
รอบเดียวเทียบได้ทั้งสองแบบ: ใน log คอลัมน์ event `PENDING` = จุดที่ถ้าไม่มีกฎจะแจ้ง ·
ตามด้วย `FALL` (แจ้งจริง) หรือ `CANCEL` (กฎตัดทิ้ง) · ยังไม่เคยทดสอบกับคนจริง ไฟล์เดิมสั้นเกินจะพิสูจน์

## ถ่ายวิดีโอ demo

ถ้าผลช่วงที่ 4 ใช้ได้: รีสตาร์ท Express ด้วย `ACK_TIMEOUT_SECONDS=60 npm run dev` (ไม่ใส่ `TWILIO_MODE=fake` · อย่าลืม 60 ไม่งั้นโทรหลัง 5 วิ) แล้วถ่ายเทคเดียว
เดินเข้ามา → ล้ม → อยู่ที่พื้น → มือถือเด้งแจ้งเตือน → ไม่มีใครกดรับใน 60 วิ → ระบบโทรออก

ถ้าผลยังไม่พอ ใช้ `POST /api/v1/demo/fire` แทนได้ แต่ต้องบอกในวิดีโอว่าเป็นการสั่งเอง ไม่ใช่โมเดลตรวจจับ

## ข้อควรระวัง

- Express กันแจ้งซ้ำต่ออุปกรณ์ (ค่าเริ่มต้น 300 วิ) — ถ้าเดินแล้วโดนแจ้งผิดก่อน การล้มจริงในช่วงนั้นจะไม่สร้างเหตุการณ์ใหม่
- `device_id` ต้องตรงกับ `devices.code` ใน Supabase ถึงจะขึ้นในแอปของบ้านนั้น (push ยังไปทุกเครื่องที่ลงทะเบียน) — และต้องทำหัวข้อ "ให้เหตุการณ์ขึ้นในแอป" ครบก่อน
- โมเดลเทรนจากห้องและจุดวางนี้เท่านั้น ย้ายบอร์ดแล้วผลเปลี่ยน
