# Runbook เก็บ Dataset ใหม่

**แผน:** 396 รอบ · ครั้งเดียวรวด · ห้องเดียว สภาพ ideal · 792 ไฟล์ (99% ของชุดเดิม)
**เวลา:** ~4.8 ชม.

> เรื่อง unseen / หลาย environment เลื่อนไว้ก่อนโดยตั้งใจ — รอบนี้เอาให้ได้ข้อมูลคุณภาพดีในห้องเดียว

---

## เลือกทางรับข้อมูลก่อน

| | USB Serial | **UDP** |
|---|---|---|
| ระยะ ESP32 ↔ คอม | จำกัดที่สาย | ไกลได้ ไม่ต้องไล่สาย |
| ต้อง flash firmware ใหม่ | ไม่ต้อง | **ต้อง** (เปิด `CONFIG_SEND_CSI_TO_UDP`) |
| ช่องสัญญาณ | คงที่ตาม `WIFI_CHANNEL` | คงที่เหมือนกัน (คอมเกาะ AP ของ ESP32) |
| คอมต่อเน็ตได้ | ได้ | **ไม่ได้** ระหว่างเก็บ |

### ถ้าใช้ UDP — ต้องทำก่อน

```bash
cd fall_detection_backend/ESP32-CSI-Tool/active_ap
idf.py menuconfig     # ESP32 CSI Tool Config → [*] Send CSI data over UDP
idf.py build && idf.py -p /dev/cu.usbserial-XXXX flash
```
⚠️ **เครื่องที่เขียนโค้ดไม่มี ESP-IDF — ต้องมีคนช่วย build/flash ก่อน**

จากนั้นให้คอม **เกาะ WiFi ที่ ESP32 ปล่อยเอง** (SSID ตาม `CONFIG_ESP_WIFI_SSID`, ค่าเริ่มต้น `myssid`)
ไม่ใช่ WiFi บ้าน · firmware ยิง broadcast มาที่ `192.168.4.255:5500` จึงไม่ต้องตั้ง IP อะไร

⚠️ **วางคอมให้ห่างจากบริเวณที่ทำท่า และห้ามขยับตลอด session** — คอมที่เกาะ AP
กลายเป็นแหล่งสัญญาณเพิ่มบนช่องเดียวกัน ถ้าขยับคอมระหว่างเก็บจะปนเข้าไปในข้อมูล

## เก็บจริง — 396 รอบ ครั้งเดียว

```bash
python data_collection/csi_collector_serial.py                    # serial
CSI_TRANSPORT=udp python data_collection/csi_collector_serial.py  # udp
#   กด s  →  ใส่ 396  →  กรอก ห้อง / ตำแหน่ง ESP32 / คนแสดง ให้ครบ
```

**ล้มจริง 396 ครั้ง ใน ~4.8 ชม.** — วางแผนพักไว้ล่วงหน้า แนะนำพัก 10 นาที
ทุก ๆ ~100 รอบ (ประมาณชั่วโมงละครั้ง) แถบ progress บอกอยู่ว่าถึงรอบที่เท่าไรแล้ว

พักได้ตลอด สคริปต์เซฟ manifest ทุก sample — แต่ **ห้ามปิดโปรแกรม / ห้ามถอดปลั๊ก ESP32**
ระหว่างพัก ไม่งั้นกลายเป็นคนละ session

### วิธีกดแต่ละ sample

| ท่า | วิธีกด |
|---|---|
| 🔴 fall | Enter **ตอนล้มถึงพื้น** (มาร์ค) → Enter อีกครั้ง **หยุด** |
| 🟢 non_fall | Enter ครั้งเดียว **หยุด** |

### จังหวะของท่า fall — สำคัญที่สุด

```
[ยืนนิ่ง / เดินปกติ ≥ 5 วินาที]  →  ล้ม  →  กด Enter ตอนถึงพื้น
   →  [นอนอยู่บนพื้นต่ออีก ~2 วิ]  →  กด Enter หยุด
```

- **ยืนนิ่งอย่างน้อย 5 วินาทีก่อนล้ม** — ถ้าล้มเร็วกว่านี้ `preprocess_v3` ตัด window
  ไม่ครบ (ต้องการ ≥ 250 packet ก่อนจุดมาร์ค) สคริปต์จะเตือนทันทีที่หน้าจอถ้าเร็วไป
- **อย่ากด Enter รัว** — ท่า fall ใช้ Enter 2 ครั้งพอดี ครั้งที่ 3 จะไปตอบคำถาม
  "บันทึกไหม?" เป็นค่าว่าง แล้วสคริปต์จะทิ้ง sample นั้น (เก็บซ้ำได้ ไม่เสียหาย)
- ปล่อยคลิปยาว ~12 วิ (แถบ progress เต็ม ≈ 900 pkt) **อย่ารีบหยุด**
- ท่า "ห้องว่าง" = ออกจากห้องไปเลย ไม่มีใครอยู่

### เช็คบนหน้าจอทุกครั้งที่เก็บท่า fall

```
รับมา 912 pkts   📍 มาร์คที่ pkt 398 (5.4 วิ)      ← ต้องเห็นบรรทัดนี้
```
ถ้าขึ้น `⚠️ ไม่มีจุดมาร์ค` หรือ `⚠️ ล้มเร็วไป` → ตอบ `n` ทิ้งแล้วเก็บใหม่

### ห้ามตลอด session

- ❌ reboot / ถอดปลั๊ก ESP32
- ❌ ขยับ ESP32 ทั้งสองตัว
- ❌ ย้ายเฟอร์นิเจอร์ / เปิด-ปิดประตูหน้าต่างเปลี่ยนไปจากเดิม
- ❌ มีคนอื่นเดินผ่าน

## หลังเก็บเสร็จ

> 🚨 **ห้ามรัน `preprocess_v2.py` กับข้อมูลชุดใหม่**
> มันตัด 300 packet แรก (= 4.1 วิแรก) ซึ่งในโปรโตคอลใหม่คือช่วง **ยืนนิ่งก่อนล้ม**
> จะได้ dataset ที่ label ว่า fall แต่เนื้อในคือคนยืนเฉย ๆ — ใช้ `preprocess_v3.py` แทน

```bash
python notebooks/preprocess_v3.py
#   → data/processed_v3_framed/      dataset A (per-window เหมือน v2)
#   → data/processed_v3_continuous/  dataset B (ต่อเนื่อง สำหรับ real-time)

CSI_DATA_DIR=data/processed_v3_framed python experiments/check_dataset.py
echo $?    # 0 = ผ่าน
```

แล้วแจ้งกลับมาพร้อมส่งไฟล์ตัวอย่าง 2-3 ไฟล์ (fall 1 · non_fall 1) เพื่อ:

- ปรับโซน label ของ dataset B ให้ตรงกับช่วงล้มจริง (ค่าตั้งต้น: กำลังล้ม = 1.5 วิก่อนถึงพื้น)
- เขียนสคริปต์ replay จำลอง real-time หา debounce / threshold ที่ถูกต้อง
